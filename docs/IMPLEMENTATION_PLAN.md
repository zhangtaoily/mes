# MES 实现方案规划

> 前置输入：PRD.md（需求）/ schema.sql（123表）/ ARCHITECTURE.md（DDD+引擎+插件混合架构）/ prototype（交互基准）
> 规划原则：**引擎先行、单域打样、逐域复制、集成收口**；阶段按依赖排序，周期依团队规模另定

## 1. 阶段总览

| 阶段 | 主题 | 交付物 | 依赖 |
|---|---|---|---|
| M0 | 工程奠基 | 可运行的 monorepo 骨架 + CI/CD + 开发规范 | 无 |
| M1 | 引擎层（mes-engine） | code / flow / meta / script 四引擎 + 单测 | M0 |
| M2 | plan 域打样（DDD范式） | 计划工艺单→生产任务→排程 全链 + 制造卡打印 | M1 |
| M3 | produce 域 | 上批/产量/启停/翻批/投料 + 领退料确认 + PDA核心接口 | M2 |
| M4 | pack + qc 域 | 包装任务→执行→装箱→组托→WMS / 检验报告+公式+方案 | M3 |
| M5 | 集成收口 | K3/WMS/打印/电子秤插件 SPI 化 + 同步补偿 | M1（可并行开发），M4 联调 |
| M6 | 报表与上线 | 60+报表（优先P0 12张）+ 性能压测 + 数据迁移演练 + 试运行 | M4 |

## 2. 各阶段工作包与验收标准

### M0 工程奠基
- **工作包**：mes-parent 多模块脚手架（bootstrap/domain/engine/plugin-api/plugins）；MyBatis-Plus + Redis + Flyway（schema.sql 转迁移脚本）；统一异常/返回体/操作日志；登录鉴权（JWT）+ 用户角色组织（sys-user 三表）；CI：提交跑单测，合并跑集成测试
- **验收**：`mvn package` 全绿；登录后能调通一个 hello 接口；Flyway 建出 123 张表；权限按钮级拦截可用

### M1 引擎层（不发版能力的地基）
- **code 编码引擎**：sys_code_rule 配置化 + Redis INCR 流水 + 按日/月重置；**验收**：并发 100 线程取号无重号，断号可追溯
- **flow 状态机**：BillStatusEnum + 迁移表 + `f(状态,角色)→按钮` 接口下发；**验收**：加一条迁移配置后按钮变化，不改代码
- **meta 元数据**：TableNode 列表列/查询项动态渲染接口；**验收**：质检方案纵表增删指标，列表页自动多列
- **script 脚本引擎**：GraalVM JS 沙箱（超时/禁IO/白名单）+ `$BQ/$SET` 注入；**验收**：不匀率公式脚本编辑即生效，死循环脚本 500ms 被杀并报行号
- 同步启动 **领域事件总线**（Spring Event 版接口先定型）

### M2 plan 域打样（DDD 范式样板）
- **工作包**：K3 订单只读镜像 + 引入K3订单（单选带出+引入量回写）；计划工艺单（7Tab+编制工艺单+分步操作）；生产任务（工艺配置引用技术/车间工艺库）；排程（生成/合并/刷新 + 任务明细PI带出+剩余可排校验）；A4 制造卡打印 + 撤回
- **聚合根**：PlanCraft / ProductionTask / Schedule；**不变量**：引入量≤订单数量、排程量≤剩余可排、工序路线完整才能生成排程
- **验收**：原型 prototype/pages 中 plan 组全部页面可对表演 walk-through；撤回后排程可重排；双击进编辑/返回列表交互一致

### M3 produce 域（现场执行，PDA 主战场）
- **工作包**：上批汇报（含批号标识/追溯批次链闭环校验）、产量/启停/翻批日志、前纺生产情况汇报、投料记录（投料完毕才能了批）、领退料确认（JDSC1L/T 单号走编码引擎）、复精梳毛球周转车、蒸纱信息、自络筒切疵
- **PDA**：上批/产量/投料扫码接口（与 PC 共用 application 层，仅 BFF 差异）
- **验收**：一票批次从上批→投料→汇报→了批在测试环境走通；追溯批次链断链时拒绝了批

### M4 pack + qc 域
- **pack**：包装任务→执行→逐箱称重→装箱→组托→箱贴/筒贴打印；五列重量恒等式（毛=皮+净、净→公重按回潮公式）作为聚合校验；倒毛包装/周转车出入库
- **qc**：抽样登记→检验报告（方案带出指标矩阵，**script 引擎在此上线**）→中心实验室（作废/取消作废）→包装质检（15疵纱分类）→公示报告
- **验收**：`$BQ` 公式算出衍生指标并参与越限判定；作废报告不计入统计且可恢复

### M5 集成收口（插件 SPI 化）
- **工作包**：k3 / wms / printer / scale / pda 从 @Service 抽到独立 jar；SPI 加载器（目录扫描+手动 reload）；sync_log 幂等（K3接口ID唯一索引）+ XXL-Job 失败重试
- **联调**：与 K3 用真实历史单据对账一轮（字段映射表：PRD 3.1 的49字段）；与 WMS 走箱号/托盘号/五列重量报文
- **验收**：模拟 K3 重推同一单不产生重复；替换 wms 插件 jar 核心服务不重启

### M6 报表与上线
- **工作包**：报表分优先级——P0（12张：车间产品质量检验日报表/筒子称重产量表/包装批次入库汇总/用毛率统计/生产进度跟踪等）先行，P1/P2（配棉分析/电耗/周期天等）后置；压测（排程刷新、产量汇报峰值、K3 同步批量）；数据迁移演练（若从参照系统切数据）；试运行 + 并行核对
- **验收**：P0 报表与手工台账核对一致；压测目标：日报表查询 P95 < 3s

## 3. 团队并行泳道

```
泳道A（后端核心）：M0 → M1 → M2 → M3 → M4
泳道B（集成）：    M0后并行 → 插件接口桩 → M5（M4起联调）
泳道C（前端）：    M0后并行 → 通用列表/表单组件(TableNode配套) → 跟随各域
泳道D（PDA）：     M3起介入
```

关键解耦点：泳道B/C 基于原型 + 接口契约（OpenAPI 先行）开发，不等后端实现。

## 4. 环境与 DevOps

- 环境：dev / test / staging（连 K3/WMS 测试套件）/ prod
- 分支：主干开发 + 功能开关（引擎配置天然是开关）；DDD 域改动走滚动发布
- 数据库变更：一律 Flyway，禁止手改库

## 5. 风险清单

| 风险 | 缓解 |
|---|---|
| K3/WMS 接口文档不全 | M0 起就向甲方索要接口规范；参照系统 sync_log 请求/返回参数截图可反推报文结构 |
| 毛纺业务口径争议（回潮/用毛率公式） | 公式全部走 script 引擎外置，口径变化不发版；上线前与质检部门书面确认 |
| PDA 弱网/离线 | 产量汇报支持本地缓存+补传（M3 工作包内） |
| 报表口径与老系统对不上 | M6 并行核对期预留；报表 SQL 走只读库，避免拖垮生产 |
| script 引擎安全 | 沙箱白名单 + 超时杀进程 + 公式变更留版本（qc_formula 版本字段） |
